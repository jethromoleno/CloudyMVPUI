# Compatibility Adapter Register

This register governs temporary compatibility behavior during the incremental Cloudy migration. Adapters do not create production persistence, authorization, RLS, concurrency, audit, or security guarantees. Business rules remain in the service/domain boundary; adapters may project shapes but must not duplicate or invent rules.

## Rules for New Work

- New page/component code imports `services`, not `services/apiService`.
- The development adapters remain reachable only through typed contracts and are labeled as non-production.
- Production auth fails closed until a separately authorized adapter exists.
- Route wrappers preserve existing behavior; new business rules are not added to them.
- Any deadline change requires an updated owner, risk, removal criterion, and accepted phase decision.

## Phase 2C editor adapter

Phase 2C added the bounded `Phase 2C Trip Editor typed projection` through `services/tripEditor.ts` and `components/TripFormPage.tsx`. It owns typed Create/Edit initialization, canonical lookups, Draft/Scheduled intents, ordered stops, and development-only mutation responses. Its in-memory version token rejects stale retries with normalized `409`/`STALE_VERSION` before local writes; it preserves local input and never auto-merges. Assignment values are read-only projections; the form does not submit driver, truck, or helper mutation fields. Browser evidence uses one worker plus a fresh context and explicit sign-in per test because development auth and mock mutations are memory-only. The adapter remains `RETAINED_NON_PRODUCTION` until an approved production authoring API provides durable versions, authorization, persistence, cancellation, and atomic transaction guarantees. The legacy TripList editor remains a temporary compatibility consumer only for non-Phase-2C schedule/map behavior.
